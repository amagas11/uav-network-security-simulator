# 固定用例与三种检测模式的对比实验

## 1. 这一步做什么

不启动前端或后端 Web 服务，直接运行现有仿真内核。对每个固定用例，分别使用仅上层检测 `APPLICATION_ONLY`、仅物理检测 `PHYSICAL_ONLY` 和联合检测 `COMBINED`，保存实际检测、防御、业务到达及中心收到的报告。

用例输入保存在 `config/detection_comparison_cases.json`，包含公共配置、每个用例的业务与攻击配置，以及必要的链路断开/恢复操作。不同模式不改变同一用例的业务、攻击参数、阈值或选定种子，只改变三种模式所对应的开关。防御会影响后续流量和上报，因此相同种子不意味着三种模式下每一次空口观测都完全相同。

所有信号仍为特征级仿真，没有真实 IQ、真实厂商数据或模型训练。本次新增的是实验组织、证据检查和结果输出，不是新的检测算法。

## 2. 十一个固定用例

| 编号 | 用例 | 实际构造与检查重点 |
| --- | --- | --- |
| `NORMAL_MULTIHOP` | 正常多跳 | 成员2经领航1到中心0；每跳比较当前发送设备，不混淆端到端业务源；检查正常执行或透明到达 |
| `SPOOF_EXTERNAL` | 外部伪装 | 外部设备复制合法帧并改变业务源声明，使用合法本跳声明；比较原有认证和射频准入 |
| `FDI_EXTERNAL_COPY` | 修改副本注入 | 原帧继续发送，外部设备额外注入修改载荷、保留旧认证的副本 |
| `FDI_EXTERNAL_REPLACEMENT` | 拦截修改替换 | 原帧到达受控外部中继，中继只向目标发送修改后的替代帧 |
| `REPLAY_EXTERNAL` | 外部重放 | 捕获合法帧后，由外部设备不改内容重发；分别观察序列检查和射频拒绝 |
| `FLOODING_EXTERNAL` | 洪泛与恢复 | 外部流量达到100帧/秒，接收阈值8帧/秒；观察总到达告警、严格白名单及压力消失后的恢复 |
| `FDI_INTERNAL_POST_HMAC` | 合法硬件HMAC后篡改 | 合法设备在业务HMAC生成后改成5000米遥测；指纹仍合法，认证可以发现内容被改 |
| `SIGNED_ABNORMAL_TELEMETRY` | 异常内容正常认证 | 合法设备直接生成5000米遥测并正常认证；用于呈现当前独立业务异常规则的缺口 |
| `LOW_SNR` | 正常弱信号 | 合法链路正常增加40dB衰减；验证低质量指纹不算确认攻击，不给它加攻击标签 |
| `REPORT_LINK_RECOVERY` | 断链补传 | 中心0与领航1之间的链路先断开，成员2被洪泛；2秒时恢复，检查本地缓存及中心延迟收到报告 |
| `PASSIVE_EAVESDROPPING` | 被动窃听边界 | 监听者实际捕获合法流量但不发射，不能被射频身份模块虚构检出或定位 |

公共仿真时长6秒、步长0.2秒、4个合法节点。大部分用例使用较高的速率阈值以避免把其他攻击的流量变化混为 DoS；洪泛与断链用例明确使用8帧/秒。每次运行会按实际接收、动作、缓存及投递结果检查，而不是看到配置里写了攻击就判定通过。

攻击拦截证据按“具体发射 -> 具体接收 -> 认证结果 -> 规则结果 -> 已执行丢弃”关联，不能用同一实验内另一条无关报文的认证失败代替。认证事件新增的 `source_event_ids` 和 `air_emission_ref` 仅为接收端本地审计编号，不是发送报文的新字段，排队延迟不会改变它们对应的接收帧。两种外部 FDI 还检查捕获、修改、原始认证、实际发送摘要和原帧去向，不能仅凭一条外部发射就认为已演示完整攻击过程。

“检查通过”表示该用例实际表现符合检查目标，不等于“所有攻击均被检出”。例如异常内容正常认证的用例，检查通过恰好说明当前系统没有拦住它，这是能力边界，不是检测成功。

## 3. 如何运行

在 `v8_platform` 目录，使用已经安装项目依赖的 Python 环境。完整运行11个用例、三种模式、三个种子，共99次实验：

```powershell
python -m tools.run_detection_comparison --output-dir runtime_datasets/comparison-run-01 --seed 0 --seed 1 --seed 42
```

输出目录必须不存在或为空。程序拒绝覆盖旧实验，请给每次实验使用新的目录名。生成目录已由项目现有 `runtime_datasets/` 忽略规则排除，不把大批原始实验数据自动加入 Git。

只运行一个用例和一种模式：

```powershell
python -m tools.run_detection_comparison --output-dir runtime_datasets/replay-check-01 --case REPLAY_EXTERNAL --mode PHYSICAL_ONLY --seed 42
```

`--case`、`--mode`、`--seed` 均可重复；不指定时默认全部用例、三种模式、种子42。`--no-export` 只生成结果和机制检查，跳过原始数据集导出及格式校验，适合快速查看；此时数据格式有效性为 null，不得描述成已通过数据校验。

命令退出码为0表示所有选定用例的机制检查以及要求执行的数据校验通过，为1表示有检查或校验失败。查看 `comparison_summary.json` 中具体的 `checks.items`、`schema_validation.errors` 定位原因，不要只看控制台的单项机制检查。

## 4. 输出在哪里、字段是什么意思

输出根目录包含：

- `comparison_report.md`：中文结果表和能力边界，可直接阅读。
- `comparison.csv`：适合 Excel 对比，带 UTF-8 BOM，列名解释见下表。
- `comparison_summary.json`：包含所有运行结果及总体状态。
- 每次运行的独立目录：`用例-模式-seed-种子/result.json`，以及默认导出的 `runs.jsonl`、`events.jsonl`、`labels.jsonl`、`schema.json` 等原始数据文件。

| 字段或列 | 中文含义 |
| --- | --- |
| `case_id` / `mode` / `seed` | 固定用例编号、实际检测模式、随机种子 |
| `scenario_fingerprint` | 不包含模式和种子的用例输入校验值；同用例三种模式应一致，种子另外记录 |
| `checks.passed` / CSV的 `checks_passed` | 本次机制及能力边界检查是否通过 |
| `checks.items` | 每条检查的名称、是否通过以及检查依据 |
| `schema_validation.valid` / `schema_valid` | 完整数据格式是否有效；未请求导出时为null |
| `application_layer.enabled` | 是否实际解析并检测业务协议 |
| `business_auth_samples` | 业务帧进入认证流程的事件数，不包含平台管理报文 |
| `crypto_failure_samples` / `crypto_failures` | 更早的封装认证失败数；尚未进入业务HMAC，不重复当成HMAC失败 |
| `hmac_failure_samples` / `hmac_failures` | 业务HMAC明确返回失败的事件数 |
| `replay_rejection_samples` / `replay_rejections` | 序列、时间戳或会话检查明确拒绝的事件数 |
| `physical_confirmed_samples` / `rff_confirmed` | 实际接收中确认物理身份异常的次数，不包括仅因低质量保护性拒绝 |
| `physical_drops` / `rff_drops` | 实际执行的射频准入丢弃次数，不把解码失败算成丢弃成功 |
| `physical_layer` | 已有独立物理评估，保留分攻击的可观测分母、检测与阻断统计 |
| `delivery.executed_business_messages` | 进入现有正常业务投递流程的数量；不能据此认定业务内容合理 |
| `delivery.opaque_delivered_frames` | 不解析业务的透明到达数量，不是业务执行成功数 |
| `reports.received_count` / `center_reports` | 中心实际收到的安全报告数，不是所有节点本地告警总数 |
| `reports.records` | 中心收到的真实报告内容及其检测、接收时间和证据编号 |
| `link_checkpoints` | 恢复链路前的本地缓存数、中心报告数、仿真时间，证明没有跳过通信过程直接上报 |
| `capability_gap` | 本用例发现或验证的能力缺口；正常认证异常内容用例会明确标记业务异常规则缺失 |

这些计数是各层实际处理的事件数，不是可相加的攻击数量。联合模式在射频阶段已拒绝的帧不会再进入业务认证，所以不能把后续HMAC失败数降低解释成联合检测变差。物理分项检测率也只对有合格输入的外部重发样本计算；没有分母时保留 null，不改填0或1。

## 5. 必须保留的能力边界

当前有两类容易混淆的 FDI：HMAC后改内容会破坏认证，而合法设备先构造恶意内容再正常认证不会破坏认证。射频指纹也不能区分同一合法硬件发出的正常和恶意载荷。固定用例如实显示后者的缺口，本次不额外补写业务异常检测算法或训练模型。

当前基线的 DoS 攻击枚举只有 Flooding，不能把不存在的 Jamming 机制加入结果并声称已经实现。弱信号用例采用正常衰减，只检查低质量观测边界，不冒充干扰型 DoS 实验。

完全被动的窃听不需要发射，没有对应物理身份异常；应当观察捕获与加密保护效果，不宣称能从射频指纹识别出静默监听者。所有结果只说明本仿真参数和固定用例下的表现，不代表真实无人机检测准确率。

## 6. 本次验收结果

2026-10-27，按种子0、1、42运行11个用例和三种模式，共99次实验。99次机制及能力边界检查通过，99份完整导出数据均通过格式校验。正式结果位于 `runtime_datasets/detection-comparison-20261027-final/`，优先阅读其中的 `comparison_report.md`；前面带编号的目录保留了调试历史，不作为最终验收结果。

专项对比测试57项通过，包含无关认证失败不能冒充攻击拒绝、空机制记录不能冒充FDI过程、实际发送摘要必须匹配、延迟认证仍对应原接收事件、旧数据格式兼容、非法注入方式仍拒绝等负向测试。独立复核发现的两项证据检查问题已修正并复核通过。

干净副本全量回归为 **782 passed**，耗时114.84秒，附一条第三方 Starlette 测试客户端弃用提示。复制时核对365个仓库及新增文件的SHA-256，代码副本不包含主目录个人资料或生成的实验数据；测试临时输出也放在副本之外。主目录额外的中文命名个人Word文件仍可能触发既有打包器的英文路径映射约束，未修改这些个人文档或打包规则。

验收通过不消除第5节的能力边界：正常认证后的异常业务内容仍有缺口，独立干扰型DoS仍未实现，被动窃听仍不能由射频身份检测直接发现。
